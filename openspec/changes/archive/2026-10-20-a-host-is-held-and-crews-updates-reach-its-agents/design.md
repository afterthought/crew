# Design

Rules relied on: `teams.2` (nothing starts over a running agent; `stop` fails rather than lies), `teams.6` (crew-role's start; herdr's bare resume drops the effort, mode and folders), `teams.7` (every agent crew starts is greeted), `teams.11` (a tell reaches its agent or not at all), `read.1` (what crew can't read stops it), `read.3` (a host that does not answer is named), `record.3` (no typed words in an entry), `code.3` (a command runs on the host it acts on), `code.7` (decisions are functions of facts), `code.8` (the bands), `code.9` (a command answers; long work is its own wait). New rule: `teams.19`.

1. **A hold is a file on the host**, `~/.local/state/crew/hold`, written by `crew _hold set` there and removed by `crew _go`. Every start crew makes goes through `Agents.start`, which refuses on a held host; each command that would start an agent refuses first, with the hold's words, so nothing is half done: a stage's start (recorded refused), a fix, a team's up, rebuild, restart or resume, a main level's up, a dispatcher's up, a review, `crew revive`, and a give, which reads the team's host's hold before it writes the plan. A hold file crew can't read holds the host (`read.1`). The run record names the host and never the why, which is the user's words (`record.3`).
2. **Drain, not stop.** A hold tells each standing agent up to finish its step and start nothing new, and lets running stages reach their deliverable. `crew hold wait` ends every agent only once nothing works: no agent working, waiting on a question, or running background work of its own other than crew's waits, no stage owed its end, and none of crew's tests running. `--now` is for when the user can't wait. Ending the agents first matters: herdr's restart resumes a running Claude bare, losing its effort, mode and folders (`teams.6`); a pane left a shell comes back a shell, and `crew go` revives it through crew with everything.
3. **What an agent loaded** is recorded at its start by the SessionStart hook: the commit and version of crew (a start that loads the plugin, a new session's or a resume's; a compaction or a /clear keeps what was recorded), and crew-role's digest of the launch, its model, effort, folders and brief (`CREW_LAUNCH`). The digest is built without the plan, since a conductor's folder is not part of what it loaded and reading it costs a fetch.
4. **Due** (`crew.update_due`): the launch digest differs, or the part of crew's plugin a session loads at its start (`hooks.json`, `status.js`, `skills/`, the manifest) changed between the start's commit and the checkout's. A change to crew's code alone makes nothing due: every command runs the checkout as it is. An agent started before crew kept these is due. When git can't tell, nothing is restarted and crew says so.
5. **The good point** is the end of the agent's turn: crew's Stop hook hands a due standing agent to `crew _renew` on its host, a process of its own (`code.9`), which waits for herdr to read it idle with no question open and no background work of its own but crew's waits, and then restarts it: a conductor fresh, as its restart always is; every other standing role with its conversation, so a planner's, ops's or the design agent's context survives, told what changed and that its background waits ended. An agent sitting idle has no turn to end, so the console's rail tab hands its partition's due agents theirs whenever crew's checkout or the teams file moves (`crew _update`), and `crew update` does it by hand. Nothing restarts while the host is held; `crew go` ends with the same sweep.
6. **The band** gets its words from `board.agent_views` (`code.8`): the views file on each host now carries, for each standing agent of the partition with a start recorded there, the crew it started on and whether it is due, and a held host's hold, so `status.js` draws them unchanged. A team's ops and a dispatcher, which had no view, get the crew line alone.
