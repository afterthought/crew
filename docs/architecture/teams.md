# Team rules

The rules for the main level's agents, panes and tells: the bash command, the role launcher and the builder. crew on `teamless/deneb` runs no team (2026-11-03, for deneb alone, record 0047 move 5): a bolt's work is Flume's places, launched through the host's runner, and the rules about slots, stages, fixes, forecasts and the team are retired below, their numbers not reused. `core.md` binds here too; the how-to is README's The main level section and `plugin/skills/crew/SKILL.md`.

## Rules

Retired 2026-11-03 for deneb alone with `the-team-machinery-leaves` on `teamless/deneb`: `teams.1` and `teams.16` (slots, the slot lent to a fix, one bolt per team; record 0045), `teams.3` (the fix slot; record 0045), `teams.4` (a stage's end and stuck read; record 0007), `teams.12`, `teams.13` and `teams.14` (Touches, forecasts, a conflict resolved in the later unit, settle), `teams.17` (verify's round and the merge stage), `teams.18` (a stage's proof as sluice's run; record 0030), `teams.20` (the branch hint), `teams.21` (the forecast on a conductor's wait; record 0036), `teams.22` and `teams.23` (a unit's hold, a stalled team; records 0044 and 0046). Their records keep the history.

- **[teams.2]** crew never starts a role over an agent still running, nor in a pane herdr lists but holds no terminal for, which whatever opens a role's pane, `crew main up`, which starts the partition's operator with the main level (record 0035), `resume`, `restart`, `crew console up`, which opens the flow, rail and board tabs and starts no agent, and `crew revive`, closes and opens again in its layout, saying so, `crew revive` then picking up the role's agent there, never touching a pane an agent holds; `stop` fails rather than lies when the agent did not exit, and a working agent is ended, cleared or freed only with `--force`.
- **[teams.5]** A unit, chore or fix merges into its bolt only through a submission to sluice, which its place under Flume makes and waits on, sluice's verdict its gate, in a kit whose `.config/sluice.toml` names its bolt branches' checks; crew starts no bolt in a kit without that policy, naming the file; nothing of crew's moves a bolt's branch, and a bolt that conflicts with main takes main by a submission to the bolt, never by a fix that replays it. (Amended 2026-11-03 for deneb alone with `the-team-machinery-leaves` on `teamless/deneb`, record 0047 move 5.)
- **[teams.6]** A role's model and effort come only from its definition's frontmatter, overridden only under `roles.<role>` in the teams file, where a partition's main-level role may also name the session of the main level's machine it runs in (record 0035); `crew-role` starts every role with `CREW_AGENT`, `CREW_LABEL`, `SLUICE_AGENT` (the agent's name again, which sluice reads) and `CREW_ROLE` (the definition its brief comes from) set and the filled brief appended to the system prompt, in the role's folder, and `crew resume` picks up the agent's last session in the folder it began in; a session herdr resumes without that environment gets its name and identity back at its start, and at each compaction its brief, built by `crew.brief` as `crew-role` builds it, as context.
- **[teams.7]** Every agent crew starts gets a first message once it is up, exactly one per start, so it has a conversation a resume after a herdr restart can pick up: the reviewer its batch, and every other agent a greeting marked as crew's, a main level's design agent, planner, ops and operator agent told to carry on with what is theirs, also when `crew revive` brings it back with its conversation. (Amended 2026-11-03 for deneb alone with `the-team-machinery-leaves` on `teamless/deneb`, record 0047 move 5.)
- **[teams.15]** Every first message crew sends an agent (`teams.7`), the reviewer's batch and a greeting, is taken or sent again: crew sends it only once the pane's agent accepts input, reads that the agent's transcript has it within a short time, sends it once more when it has not, and reports the start as not taken when the second sending is not taken either; text left typed in a pane for a hand to submit is never an agent's state. (Amended 2026-11-03 for deneb alone with `the-team-machinery-leaves` on `teamless/deneb`, record 0047 move 5.)
- **[teams.19]** A host is held by `crew hold` until `crew go`: while it is held crew starts no agent there and refuses every command that would, each standing agent up there is told to finish its step and start nothing new, a stage already running ends as it would, and every crew agent there is ended, its pane kept, only once nothing works there (`crew hold wait`) or at once on `--now`; and a standing agent whose brief, model, effort or folders, or the part of crew's plugin a session loads at its start, changed since its start is due a restart, which crew gives it once herdr reads it idle with no question open and no background work of its own but crew's waits, every standing role resuming its conversation, told what changed, never on a held host. (Amended 2026-11-03 for deneb alone with `the-team-machinery-leaves` on `teamless/deneb`, record 0047 move 5.)
- **[teams.24]** A crew agent submits, launches or posts and goes on: a submission's outcome, a place's end and a card's answer reach it as the tool's own push into its session, sluice's, Flume's and Pending You's, each delivered once and marked told on the record (record 0048, pattern 5; sluice record 0068, flume record 0009); a background command that blocks on the event is the session's own only where nothing on its host pushes that fact, never beside the push; crew keeps no waiting process of its own; every wait is recorded where its subject lives, the bolt's row, sluice's queue or Pending You, and a crew agent that comes back reads its rows and its cards and starts again only a wait nothing pushes, crew building no reconnect of its own, the start-time ask being a launched role's under Flume (record 0047, move 6). (Record 0046, accepted by the user 2026-10-28.)
- **[teams.11]** A tell reaches its agent as a prompt or not at all: an agent that is not up, or waiting on a question in its pane, is reported and the command fails with nothing typed.
- **[teams.8]** A pane crew starts answers only Claude's folder-trust question, never the Bypass Permissions warning.
- **[teams.9]** The panes and layout files change only by writing a new file and moving it over the old; output that bash evals is shell assignments quoted with `shlex.quote`, and everything else such a command says goes to standard error.
- **[teams.10]** A brief fills every `{{TOKEN}}` from the builder, a token with no builder or no data is a refusal, never blank text, and every brief carries the roster with how to read crew's marks.
