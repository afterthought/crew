# Core rules

The rules every change to crew holds to, wherever it is made. A rule that binds one area is on that area's page in this directory, which loads when a file under its paths is read. The reasoning behind a rule that came from a decision is in the record its details name, under `docs/adr/`. What is accepted but not yet built, and the code that stands against a rule today, is in `_open.md`.

## Rules

State

- **[state.1]** Every write to a flywheel's branch is one commit made by a crew command that fetches the tip into crew's bare cache, applies its change there, checks the result with `recfix --check` and crew's own rules, commits only its own paths through a temporary index, and pushes without force; a refused push is applied again to the new tip, and nothing is ever merged.
- **[state.2]** The plan holds only intent and the marks on it; every stage is read from the kits, and nothing records by hand how far work has got.
- **[state.3]** A kit's main moves only through sluice: by the partition's main-level ops's submission of a bolt whose verification is green, on the user's word, a fix for a landing that broke main among them, that fix a bolt of one chore until Flume's fix kind runs on main and from then a fix place Flume launches on main itself, by main-level ops or the user on reading the red, submitted to main through sluice with no bolt between and nothing moved or dropped for it (record 0047 as amended 2026-10-30, accepted by the user the same day; flume record 0023 likewise), and by a submission from a branch, `wt submit main`, of the user's own commits and the design agent's records under `docs/`; nothing is committed on a kit's main directly, and nothing else of a kit's code or specs reaches it.
- **[state.4]** crew runs no service: state is recutils files any clone reads with `recsel`, and every view is computed from those files and the run record with nothing running and nothing written.
- **[state.5]** Nothing crew runs, and nothing a brief tells an agent to run, pushes with force; crew's only pushes go to `<label>/main` of a state repository.

Roles

- **[roles.1]** The planner changes the plan only by a proposal the user approves, and crew itself refuses any direct plan write by an agent outside the role table: a conductor splits, orders and sets `After` within its own bolt and agrees to proposals, the design agent queues, a dispatcher gives bolts, main-level ops lands them, the user writes anything.
- **[roles.2]** An approval, a landing, a push to a main or a change to the teams is run only on the user's word, never on an agent's own judgment; a deploy runs on the environment's policy, `auto` given once by the user or `manual` given per deploy through the rail's card, never by an agent; crew records who ran or approved it and in which session, and does not refuse it by caller.
- **[roles.3]** When an agent breaks a rule its brief already states, the fix adds a check in crew that refuses the act, not only firmer wording in the brief.
- **[roles.4]** Every message crew or an agent sends another agent goes through `crew tell`, and everything crew types into a pane is marked, `[crew tell from <sender>]` or `[crew]`; a stage's own prompt is the one unmarked text, recognised by its form.
- **[roles.5]** crew is the wrapper of Flume, sluice, Tailrace and Pending You: it keeps the plan, the give, the readings, the cards and the briefs, and builds no mechanism one of those tools is designed to hold; a mechanism of crew's moves to its tool when that tool runs it on the host, and until then crew changes only by a removal, a reading, or a stopgap named in the record that calls for it with the move that retires it and listed in `_open.md` until it leaves. (Record 0047, accepted by the user 2026-10-28.)
- **[roles.6]** Records are the truth and are pulled; a message is a notice to one named recipient, delivered through the host's multiplexer into the session's one inbox, naming the record to read and carrying no fact to act on blindly; delivery is at least once, the sender marking the record delivered and a session's start collecting what is pending for it; an agent submits and is delivered its outcome, and background-waits on nothing a tool pushes on the same host; no bus, and no daemon any tool requires. (Record 0048, accepted by the user 2026-10-28.)
- **[roles.7]** Once Flume runs on a host, every place crew launches names its recipient by a role's address, never a session; a role with no live run is woken by Flume, never by a process of crew's; a role run's start is the one collector of what is pending for it; and a role's work that lands is a place Flume submits, never a session's submit. (Record 0049, accepted by the user 2026-10-28.)
- **[roles.8]** Every change to crew lands on main in place and keeps every team's current path working: Flume support sits behind a per-team setting in `teams.json`, written for every team by swancloud and off until the team moves, a team with it off runs today's path unchanged, teams move one at a time on the user's word, and the old path leaves crew in a landing of its own once no team uses it. (Record 0050, accepted by the user 2026-10-29.)
- **[roles.9]** crew is the control plane until a flywheel's own replaces it: a repository is registered there, by its forge address, default branch, hosts and stream on each, on the user's word; a thin runner on each host pulls what the control plane wants of it, keeps each registered repository's bare clone hidden in its own data directory and its detached view under the views' root its host configuration sets, moving a view only while it is clean and where the runner last put it, and turns each launch it is given into `flume launch` naming `--stream`, `--priority` and `--intent`, carrying Flume's ends back as records; swancloud keeps the machine and no repository, space or team. (Record 0052, accepted by the user 2026-10-30.)

Reading

- **[read.1]** When crew cannot read something a decision depends on, it refuses, or removes nothing, and names what it could not read; it never falls back to a default or a guess, and a stage it cannot tell is `unknown`, never another stage.
- **[read.2]** crew reads another tool's output only by facts checked against the tool as it is now, and guards an absent field so a missing value never becomes text.
- **[read.3]** A command that reads several hosts names each host that does not answer and still shows everything else.
- **[read.4]** crew never takes over something it did not make for the work in hand: an existing place or branch, a pane whose agent still runs, or a worktree outside its own layout is refused or left alone.
- **[read.5]** The run record is read from the flywheel's branch alone: every entry reaches the branch as it is written, as its own commit from the host that wrote it, and no decision reads a host over ssh for the record; a host is read over ssh only for the stages of its own kits' worktrees, and a host that does not answer hides only the work on it, never another host's landing nor the partition's batch clock. (Record 0029, accepted by the user on its card 2026-10-14; built by `the-run-record-reaches-the-branch-as-it-is-written`, landed 2026-10-23, with which `plan.2`'s carry clause went.)

Code

- **[code.1]** crew's Python imports nothing outside the standard library and its own modules; `gather.py` imports only the standard library, since it is piped to hosts whose crew may be older; devenv declares only jq, proto, recutils and git-cliff, with convco for its commit-msg hook; `.prototools` pins moon, Python at the minor the hosts run crew on, and uv; pytest, the tests' one dependency, is locked in `tests/uv.lock` and synced by moon.
- **[code.2]** A refusal is a `Refusal` raised through `fail()`, turned into `sys.exit(<message>)` at each entry point, never a traceback.
- **[code.3]** Every bash command about a team, main level or slot forwards to the host the teams file names before touching any state, carrying the asker's `CREW_AGENT`, `CREW_LABEL` and `CREW_SESSION`; every ssh crew runs passes `-o BatchMode=yes`.
- **[code.4]** Every name crew mints or accepts matches `^[a-z0-9][a-z0-9-]*$`.
- **[code.5]** crew reads `teams.json` (version 2) and `herdr-hosts.json`, checks every entry before any is used, and never writes either; no field has a default.
- **[code.6]** Every commit is a Conventional Commit, staged by path; `git add -A`, `git stash` and `git reset` are never used.
- **[code.7]** A decision of crew's is a function of plain facts that starts no process and calls no tool; the reads that feed it and the acts that follow it stay thin around it, and a decision in `plugin/bin/crew`'s bash moves to Python when its test is converted.
- **[code.8]** A change to what crew models, its bolts, units, stages, proposals, explorations and elaborations, cards and rail rows, updates in the same change, each with its cases, the agents' views of it, `board.agent_views`, and the mod that draws them above each agent's prompt, `plugin/hooks/status.js`.
- **[code.9]** A crew command answers within the time an agent's shell gives one command by default: a write answers once its commit is made and what it set in motion is handed to the host that runs it, and work that can take longer, a stage, a review, a proof, is started by one command and waited for by its own wait, which takes a timeout.
- **[code.10]** crew is released as `v<x.y.z>` tags on main: on each push to main, CI tags the pushed commit when git-cliff finds a new version in the conventional commits since the last tag, and publishes a GitHub release whose notes are git-cliff's for that range (`cliff.toml`); the version is kept in no file, and a tag is never moved.

## Details

**[state.1]** Rules out: a checkout of the state branch; a merge of two appended records; `merge=union`; a push with `+`. Source: `bolt-plan` spec "Writes go through crew and are never merged"; `flywheel-state` spec; `plan.py` `land`, 318–389; ADR 0003 for what "held" means. Read 2026-10-27 (madswan signal 2026-10-27-swancloud-operator-cbefe4ba/02): `land` applies a refused push again at once, five replays and no wait between them, so a run-record push to a branch taking a commit every few seconds, as madswan/main did at 17:33Z with nineteen commits in two minutes, can lose every replay inside ten seconds and be kept for the host's next entry (`record.2`), the branch then lacking an entry `read.5` says it holds as written. The rule's outcome stands: a write is applied again to the new tip until it lands, and a branch that is merely busy is outwaited, not given up on; a replay that waits a growing moment before it fetches again changes no rule and is a crew chore, the kept entry staying the fallback for a branch that will not take it.

**[state.2]** Rules out: a `Stage` or `Date` field in `plan.rec`; a status file beside the plan. Not ruled out: the marks `Amended` and, once built, `Hold`. Source: `bolt-plan` spec "A unit's stage is read from the kits"; `plan.py` 71–94.

**[state.3]** Amended 2026-10-16 by record 0032 (accepted 2026-10-18): a kit's main checkout is a detached anchor the fleet's timer moves, never brought level by crew, ops or an agent, and a record's or the user's branch is cut from `origin/main` (`plan.18`). Rules out: a commit made on a kit's main, by an agent or the user, which sluice's guard refuses once its hook is installed in the kit (sluice `crates/sluice/src/protect.rs`, read 2026-10-13); a unit, chore or archive committed straight to main; a landing by `wt merge`, with or without `--no-hooks`. Not ruled out: the user's own commits and the design agent's records, made on a branch in a worktree of their own and submitted with `wt submit main`, the kit's main checkout then brought level (the user, 2026-10-13, in the recovery session, asked whether commits straight onto main go through sluice: "Yes, through sluice"; record 0026); a fix on main after a landing broke it, which main-level ops lands on the user's word by a submission and never writes: the planner proposes it as a bolt of its own, first among the planned, so the dispatcher gives it to the next team that frees, the user giving it by hand to a team of their choosing when they will not wait, `crew bolt give` being the user's own and the dispatcher's, never the planner's or ops's, and no proposal naming a team (wldn-planner, 2026-10-30, on a fix bolt waiting while the team that wrote the fix was busy; `plan.may_write`, read that day) (the `main-level` spec; `main-ops.md`, "never edit the code yourself"; swancloud-ops, 2026-10-11, on the landing-card check), never a fix riding a bolt the team holds for other work, which in wldn on 2026-10-29 cost a unit in construct its place (signal 2026-10-29-swb-4-conductor-ad4cb5f9/01), and, once Flume's fix kind runs on main, a fix place of that kind launched on main, cut from its current revision with the failure's words as its brief, the launch holding its submission and the user's send through ops being the retry (record 0047 as amended 2026-10-30, accepted by the user the same day; flume record 0023, accepted 2026-10-30); the user's own work, as the archive sweep of 2026-10-10 was (crew a3caf5b to 94e31e3, swancloud 4fee795 to 54f849f, run on the user's word, nothing pushed), which `roles.1` already allows, now submitted as above. Source: `bolt-teams` spec "A bolt lands on main on the user's word"; `main-level` spec; ADR 0006 drivers; record 0026; `main-ops.md`; `design.md` *Elaboration on main*; CLAUDE.md *This checkout is live*.

**[state.4]** Rules out: a daemon; a view that commits or appends on refresh.
